## Research Context
- The current article direction is an IEEE-style study of SLA-aware and resource-efficient 5G/O-RAN slicing with online heuristics and offline metaheuristics, not a DRL-first article.
- DRL, SAC, DDQN, and predictive SAC remain implemented and useful as future baselines/extensions, but do not treat them as the active contribution unless the user explicitly reopens the DRL track.
- The active scientific contribution is comparing online heuristic slice policies against offline metaheuristic PRB-weight optimization, including a hybrid metaheuristic that combines GA diversity, PSO convergence, and SA local escape.
- The ns-3 scenario and scheduler implementation for this work live under `ns-3-dev/scratch/rslaq/`; changes to the heuristic/metaheuristic path should stay aligned with that scenario wiring and `RslaqMacScheduler`.
- `reward_mode="paper"` and `reward_mode="resource_efficient"` remain relevant for reward-derived DRL analyses, but the current heuristic/metaheuristic article should primarily report network-only C++ metrics (`summary.csv`, `timeseries.csv`, `slice_alloc.csv`) unless reward metrics are explicitly recomputed and labelled.

## RSLAQ Reward Context
- `src/environments/rslaq_reward.py` computes the reward from per-slice KPIs using slice ids `0=eMBB`, `1=URLLC`, `2=MTC`; default paper weights are `alpha=0.3333`, `beta=0.4000`, `gamma=0.2667`.
- In `reward_mode="paper"`, the reward follows the RSLAQ paper: `h_1` is normalized average eMBB throughput, `h_2=exp(-normalized URLLC max buffer)`, `h_3` is normalized average MTC throughput, and `opt_reward=alpha*h_1 + beta*h_2 + gamma*h_3 + 1/scheduler_cost` when scheduler selection is present.
- Terminal SLA logic: confirmed outage gives negative reward `-sum(slice_weights)` and can terminate; soft SLA violation gives reward `0`; otherwise the reward is `opt_reward`. Warmup and consecutive-outage filtering intentionally reduce simulator jitter effects.
- `reward_mode="resource_efficient"` adds shaping on top of the paper reward using active demand, PRB allocation match, over/under-allocation, served fraction, eMBB soft-SLA guard, and action smoothness. Use it only when evaluating the user's resource-efficiency contribution.
- Current article resource-efficient defaults are `resource_efficiency_weight=0.25`, `need_match_weight=0.30`, `waste_penalty_weight=0.35`, `under_allocation_penalty_weight=0.15`, `embb_soft_guard_penalty_weight=0.25`, `embb_soft_guard_ratio=0.80`, `action_smoothness_weight=0.05`, `resource_dynamic_need_weight=0.75`, and `resource_waste_deadband=0.03`.
- Resource-efficiency diagnostics (`resource_efficiency`, `need_allocation_match`, `over_allocation`, `under_allocation`, `embb_soft_guard_penalty`, `action_smoothness_penalty`, `resource_efficient_shaping`) are now exposed in reward terms for both `paper` and `resource_efficient`; in `paper`, shaping is `0.0` and reward remains paper-faithful.
- Resource-efficient shaping must not dilute Eq. 12 SLA outcomes: confirmed outage remains the negative slice-weight sum, soft SLA violation remains `0.0`, and shaping is only added when there is no SLA violation.
- Accepted aliases for resource-efficient reward include `resource_efficient`, `efficient_resource`, `efficiente_resource`, `efficient`, and `slice_efficient`, but prefer canonical `resource_efficient` in scripts and papers.

## RSLAQ Predictive Context
- `src/environments/rslaq_predictive.py` supports two forecast data sources: DRL `step_metrics.csv` logs and ns-3 network-only baseline `timeseries.csv` files under `ns-3-dev/results_rslaq_network_only`; `build_forecast_sequences(..., source_format="auto")` can read both, while `source_format="baseline"` forces baseline-only ingestion.
- Baseline predictive ingestion aggregates per-UE `timeseries.csv` rows to per-slice metrics, uses `slice_alloc.csv` when available for PRB/resource-share actions, and recomputes frame rewards plus SLA flags with `compute_rslaq_reward(..., reward_mode="resource_efficient")` using the current article resource-efficient weights so forecaster labels match the user's article contribution.
- `examples/rslaq_train_forecaster.py` now defaults to `../ns-3-dev/results_rslaq_network_only` and has `--source_format {auto,step_metrics,baseline}`; use `--source_format baseline` for the current intended workflow.
- `examples/rslaq_train_predictive_sac.py` now defaults to `--reward_mode resource_efficient`, `--p_sta_static_fraction 0.25`, and accepts the same resource-efficient reward weights plus eMBB soft-guard flags as DDQN/SAC.
- `examples/run_predictive_rslaq_validation.sh` trains the forecaster from `ns-3-dev/results_rslaq_network_only` by default (`FORECAST_SOURCE_FORMAT=baseline`), then runs predictive SAC with resource-efficient reward, `P_STA_STATIC_FRACTION=0.25`, and the current article resource-efficient weights. It supports `RUN_FORECASTER`, `RUN_PREDICTIVE_SAC`, `RUN_COMPARISON`, and `BUILD_NS3` toggles for smoke tests and reuse.

## RSLAQ 5G Scenario Context
- The ns-3 RSLAQ topology in `ns-3-dev/scratch/rslaq/rslaq-sim.cc` is `remoteHost -> 100Gbps P2P -> PGW/EPC -> 1 NR gNB -> static NR UEs`; there is no handover or multi-cell behavior.
- UEs are placed uniformly in a fixed disc around the gNB and assigned by contiguous UE ID ranges to slices `0=eMBB`, `1=URLLC`, `2=MTC`; each UE has one UDP downlink flow from `remoteHost`, with destination port used to map FlowMonitor results back to UE and slice.
- Default PHY/channel profile is 3.55 GHz, 100 MHz, numerology `mu=1` (30 kHz SCS), 3GPP UMi channel, configurable shadowing, panel-like gNB antenna, and isotropic UE antennas.
- `InitScenarios()` defines five traffic profiles (`low_traffic`, `normal`, `congestion`, `stressed`, `insufficient_resources`) with per-slice UE counts, total downlink rates, and packet sizes; per-UE traffic is `slice_rate / slice_ue_count`.
- `pure_rr`, `pure_pf`, and `pure_bcqi` use native 5G-LENA schedulers. `slice_*`, `slice_weighted_*`, `psta_equal`, and `slice_custom` use `RslaqMacScheduler`, which partitions RBG/PRB budget by slice weights, redistributes budget away from inactive slices, and applies RR/PF/BCQI within each slice.
- In IPC/Gym mode (`--simId` present), ns-3 writes delta KPIs to `rslaq-kpms.txt`, signals Python through POSIX semaphores, reads `rslaq_actions_for_ns3.csv`, and applies final PRB percentages plus optional scheduler IDs directly to `RslaqMacScheduler`.

## RSLAQ Heuristic And Metaheuristic Context
- New heuristic baseline modes in `rslaq-sim.cc` are `slice_demand_greedy`, `slice_sla_greedy`, `slice_least_waste`, `slice_qos_mixed`, and `slice_random_vine`. They keep the existing baseline modes intact and use `RslaqMacScheduler::SliceWeightPolicy` to compute effective PRB/RBG shares online instead of relying on the fixed RSLAQ paper weights.
- `slice_demand_greedy` allocates from active MAC demand/backlog; `slice_sla_greedy` adds SLA/buffer urgency; `slice_least_waste` aggressively follows active demand to reduce idle allocation; `slice_qos_mixed` uses SLA-greedy weights plus per-slice algorithms `eMBB=PF`, `URLLC=BCQI`, `MTC=RR`; `slice_random_vine` is a random-weight baseline inspired by R-VINE, useful as a non-optimized comparator.
- For heuristic modes, `metadata.json` records `slice_weight_policy`, and `slice_alloc.csv` column `configured_weight` now reflects the per-scheduling-decision effective weight used by the policy, not a static configured paper weight.
- `ns-3-dev/run_all_scenarios.sh` now includes the five heuristic modes by default, so the default matrix is 5 scenarios x 15 modes. Use `BASELINE_MODES=...` to narrow smoke tests or to compare only classic baselines versus heuristics.
- Offline meta-heuristic search lives in `ns-o-ran-gym/examples/run_rslaq_metaheuristics.py`. It supports `--method {ga,pso,sa,hybrid,all}` and repeatedly runs ns-3 `baselineMode=slice_custom` candidates to optimize only static `[eMBB,URLLC,MTC]` PRB weights; it does not currently optimize the intra-slice scheduler algorithm.
- `--method hybrid` is the active article metaheuristic candidate: it seeds plausible slice-weight priors, keeps elite candidates, uses PSO-style movement toward personal/global best weights, uses GA crossover/mutation for diversity, and applies SA-style local refinement around the current best.
- The meta-heuristic runner writes `metaheuristic_results.csv` and `best_candidate.json` under `ns-3-dev/results_rslaq_metaheuristics/metaheuristic_search/` by default. The score is KPI-based and penalizes MTC starvation and high URLLC delay, so do not interpret it as the RSLAQ paper reward.
- The article evaluation should compare online heuristics and offline metaheuristics on held-out seeds/scenarios using SLA per slice, temporal SLA satisfaction from `timeseries.csv`, URLLC delay p95/p99, offered-load satisfaction, PRB share efficiency from `slice_alloc.csv`, and allocation smoothness.
- Keep DRL/predictive SAC comparisons out of the main claim for now. If later included, report both network-only C++ metrics and reward-derived metrics separately; the C++ `SLA_MIN_MBPS` summary metric is not identical to the Python RSLAQ paper SLA logic.

## RSLAQ CLI Gotchas
- `ns-o-ran-gym/run_training.sh` is stale in this checkout: it passes unsupported flags such as `--apply_p_sta False`, `--mtc_is_no_policy`, and `--use_real_bfs`. Use the current `rslaq_train_*.py` argparse options or `examples/run_controlled_rslaq_validation.sh` instead.
- Current training scripts disable P_STA with `--no-apply-p-sta`; there is no `--apply_p_sta False` option. Controlled paper lines keep `P_STA_STATIC_FRACTION=0.5`, while controlled `ddqn_resource_efficient` and `sac_resource_efficient` use `RESOURCE_EFFICIENT_P_STA_STATIC_FRACTION=0.25` by default.
- DDQN defaults to `action_mode=discrete`, `include_scheduler=True`, and a 198-action table. With scheduler disabled, the table has 66 actions. DDQN now also accepts `--reward_mode resource_efficient` plus the resource reward weights.
- SAC defaults to `action_mode=continuous` and `reward_mode=paper`; resource-efficient SAC is selected with `--reward_mode resource_efficient` plus the resource reward weights. Predictive SAC defaults to `reward_mode=resource_efficient` and `p_sta_static_fraction=0.25`.
- DDQN, SAC, and predictive SAC now support deterministic post-training evaluation with `--eval_episodes`, `--eval_seed_offset`, and `--eval_seed_cycle`. `--eval_episodes=0` preserves train-only behavior; when positive, scripts write `evaluation_log.csv` and add `evaluation_metrics` to the summary JSON.
- Deterministic evaluation policy is intentionally different from training exploration: DDQN evaluates with `epsilon=0`; SAC and predictive SAC evaluate with `tanh(mean)` instead of `actor.sample`. Use these evaluation metrics for fair DRL-vs-baseline conclusions rather than late-training exploratory KPIs.
- `examples/run_controlled_rslaq_validation.sh` now compares six lines by default: `ddqn_paper`, `ddqn_resource_efficient`, `sac_paper`, `sac_resource_efficient`, and `predictive_sac`, plus optional ns-3 baselines. The predictive SAC line trains a forecaster from the campaign's own baseline data (`${OUTPUT_ROOT}/baseline_ns3/results_rslaq_network_only/`) and then runs predictive SAC with resource-efficient reward and `P_STA_STATIC_FRACTION=0.25`. Use `RUN_PREDICTIVE_SAC=0` or `RUN_DRL_COMPARISON=0` to narrow smoke runs; set `FORECASTER_CHECKPOINT=/path/to/forecaster_best.pt` to reuse an existing forecaster without retraining.
- Controlled runner replicate knobs: `TRAINING_REPLICATES` (default `1`) and `TRAINING_REPLICATE_SEED_STRIDE` (default `1000`) derive independent training seeds from each labelled seed. With one replicate, output names stay `..._seed<seed>`; with multiple replicates, output names become `..._seed<seed>_rep<N>`. Do not treat repeated identical `--seed` runs as independent replicates.
- Controlled runner evaluation knobs: `EVAL_EPISODES`, `EVAL_SEED_OFFSET`, and `EVAL_SEED_CYCLE` are passed to DDQN/SAC/predictive SAC. When `EVAL_EPISODES>0`, the internal controlled comparison prefers evaluation step metrics by filtering `step_metrics.csv` on the evaluation seed range; otherwise it uses the late-training proxy as before.
- `observation_mode=paper` is the production path with observation shape `(4, 4)`; `debug` is a separate `(3, 5)` shape.

## Runtime Contracts
- Canonical RSLAQ slice IDs are 0-based everywhere current code controls: `0=eMBB`, `1=URLLC`, `2=MTC`. `src/environments/rslaq_slice_ids.py` only tolerates legacy 1-based IDs with a warning.
- P_STA formula is implemented in Python action conversion: `p_final = static_fraction * weights + (1 - static_fraction) * p_opt`, default weights `0.3333,0.4000,0.2667`.
- `rslaq-sim.cc` does not reapply P_STA in IPC mode; it reads final PRB percentages from `rslaq_actions_for_ns3.csv`, normalizes them, and applies them directly to `RslaqMacScheduler`.
- `RslaqEnv` passes `skip_configuration=True`; scenario configuration keys become ns-3 CLI flags such as `--scenario`, `--simTime`, `--appStart`, `--periodMs`, `--seed`, and `--simId`.
- `RslaqEnv.reset()` derives the active ns-3 seed as `_base_seed + floor((episode_count - 1) / seed_cycle)`. Controlled campaigns default `SEED_CYCLE=999999`, so training uses a fixed ns-3 seed per run unless explicitly changed; deterministic evaluation resets `_base_seed` to `seed + eval_seed_offset` and usually uses `eval_seed_cycle=1`.
- `rslaq_actions_for_ns3.csv` may have a header. C++ parses `sliceId` from column 1, `dedicatedPRB` from column 2, and scheduler algorithm from column 5 when present.
